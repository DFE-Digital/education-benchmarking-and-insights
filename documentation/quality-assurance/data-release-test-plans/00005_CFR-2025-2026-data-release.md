# Test Plan: CFR Data Release – 2025-2026

## Purpose

This plan defines the QA strategy to validate the Data Release for the **Consistent Financial Reporting (CFR) covering the 2025-2026 period**.
The primary focus is ensuring the integrity of the ingestion and transformation pipeline for the CFR 2025-2026 data (raw input file `CFR_24_25_Data.csv`) into the FBIT platform, the accurate integration of ancillary datasets, and the verification of data availability and accuracy within the service.

Two additional considerations apply to this release compared to prior years:

1. **LAA released alongside CFR but not yet ready.** The Local Authority (LAA) risk-scores work is planned for release alongside CFR but is **not ready** for this release. A feature has been implemented to run the pipeline **without** the LAA updates (the `DeriveLaaRiskScores` pipeline flag set to `false`), so CFR can be released independently. This plan verifies CFR releases cleanly with LAA derivation disabled.
2. **Two outputs now produced by the pipeline require SQL-parity validation before use.** For the first time, both the **maintained schools master list** (produced by the pipeline after ingesting `CFR_24_25_Data.csv`) and the **CFR transparency file** are generated by the **data pipeline** rather than by the legacy SQL process. For each, the pipeline-produced file must be compared against the equivalent SQL-produced file and match with **zero variance**. Decision rule for both:
   - **If identical (zero variance):** adopt the **pipeline-produced** file as the source of truth for this release.
   - **If different:** fall back to the **SQL-produced** file for this release, and defer the fix to the pipeline production to a later release.

## Scope

### In Scope

- **Schema & Structural Validation:** Strict contract checking for the primary CFR input file (`maintained_schools_master_list.csv`) and all listed ancillary datasets (GIAS, Census, SEN, CDC, KS2/4, ILR) within this Data Release.
- **End-to-End (E2E) Pipeline:** Monitoring of the data release process from raw file landing to database persistence, ensuring no silent drops or transformation failures.
- **Data Reconciliation:** Ensuring database records, row counts, and key joins (school identifiers) match source file totals and counts.
- **Service/UI Validation:** Functional verification of the FBIT front-end for the 2026 reporting year for maintained schools.
- **Regression Testing:** Verification that historical CFR data (2025 and prior) remains unchanged during this data release.
- **CFR 2025-2026 Transparency File Integration:** Validation of the transparency dataset generated against the input files.
- **Maintained Schools Master List Parity (Pipeline vs SQL):** Comparison of the pipeline-produced maintained schools master list against the SQL-produced equivalent, requiring **zero variance**; adopt the pipeline file if identical, otherwise fall back to SQL.
- **Transparency File Parity (Pipeline vs SQL):** Comparison of the pipeline-produced transparency file against the SQL-produced equivalent, requiring **zero variance**; adopt the pipeline file if identical, otherwise fall back to SQL.
- **LAA-Disabled Pipeline Run:** Verification that the pipeline runs and completes CFR successfully with LAA derivation disabled (`DeriveLaaRiskScores = false`), producing no LAA artifacts and leaving CFR outputs unaffected.

### Out of Scope

- Validation of the accuracy of data within the raw source files (upstream responsibility of Data Analysts).
- Delivery/validation of the **LAA risk-scores** outputs themselves (deferred to a separate release once LAA is ready).

## Test Activities & Methodologies

### Schema & File Integrity Validation

**Goal:** Ensure structural integrity to prevent pipeline failures and schema-level data loss during the data release.

- **Constraint Checking:** Validate headers, data types (String, Decimal, Date), and mandatory/non-nullable fields (URNs, numeric fields).
- **Identifier Consistency:** Verify URNs follow the standard format and that value formats are valid across all primary and ancillary files.
- **Uniqueness:** Confirm no duplicate records within the primary CFR dataset.

### Ancillary Data & Completeness Reporting

**Goal:** Quantify "Data Readiness" and identify gaps before final processing.

- **Cross-Reference Validation:** Ensure ancillary data (e.g., KS2/KS4, SEN) correctly maps to the URNs present in the primary CFR dataset.
- **Metrics Generation:**
  - **Volume Check:** Record count comparison and identification of schools missing specific ancillary data pieces.
  - **Orphan Reporting:** Capture counts of missing data by ancillary type (e.g., number of schools without `ks2.xlsx` data).
  - **Summary Table:** Produce a completeness table indicating how many schools have missing ancillary data.

### Database & Pipeline Validation

**Goal:** Ensure data persistence and relational integrity.

- **Transformation Monitoring:** Trigger CFR ingestion and monitor logs for processing successes, silent drops, or duplicates.
- **Relational Joins:** Query the database to validate that mappings derived from ancillary sources are present, consistent, and correctly joined to school identifiers.
- **Regression Guardrails:** Run checksums and regression queries on historical CFR data to ensure no accidental overwrites occurred.

### LAA-Disabled Pipeline Run

**Goal:** Confirm CFR can be released independently while LAA is not ready.

- **Flag Verification:** Trigger the pipeline with `DeriveLaaRiskScores = false` and confirm the run completes CFR end-to-end without attempting LAA derivation.
- **No LAA Artifacts:** Confirm no LAA risk-score outputs (download file, `riskindicators`/`riskindicatorsheaders` tables) are produced or written for this release.
- **CFR Unaffected:** Confirm CFR outputs, tables, and the transparency file are identical whether or not LAA derivation is disabled (LAA being off must have no side effects on CFR).

### Maintained Schools Master List Parity (Pipeline vs SQL)

**Goal:** Confirm the maintained schools master list produced by the pipeline (after ingesting `CFR_24_25_Data.csv`) exactly reproduces the SQL-produced master list before the pipeline output is adopted.

- **Generation:** Produce the maintained schools master list via the pipeline (after ingesting `CFR_24_25_Data.csv`).
- **Baseline:** Obtain the SQL-produced master list for the same period as the comparison baseline.
- **Schema Parity:** Confirm identical column set, column order, naming, data types, number/date formatting, and encoding.
- **Row/Population Parity:** Confirm identical school set and row count (no schools added or dropped).
- **Value Parity zero variance:** Perform a full-population, cell-by-cell comparison of every field. Any non-zero difference is a defect; agree the numeric tolerance up front (SQL `DECIMAL` vs pipeline float rounding is expected diff).
- **Decision rule:** If identical (zero variance), adopt the **pipeline-produced** master list for this release. If different, fall back to the **SQL-produced** master list for this release and defer the pipeline fix to a later release.

### Transparency File Parity (Pipeline vs SQL)

**Goal:** Confirm the pipeline-produced transparency file exactly reproduces the SQL-produced transparency file before the pipeline output is adopted.

- **Generation:** Produce the transparency file via the pipeline (`GenerateTransparencyFilesAndPrecursorFiles = true`).
- **Baseline:** Obtain the SQL-produced transparency file for the same period as the comparison baseline.
- **Schema Parity:** Confirm identical column set, column order, naming, data types, number/date formatting, and encoding.
- **Row/Population Parity:** Confirm identical school set and row count (no schools added or dropped).
- **Value Parity zero variance:** Perform a full-population, cell-by-cell comparison of every derived field (e.g. Total Income, Total Expenditure, Community Grants, Direct/Targeted Grants, per-pupil figures, balances). Any non-zero difference is a defect; agree the numeric tolerance up front (SQL `DECIMAL` vs pipeline float rounding is the expected source of spurious diffs).
- **Decision rule:** If identical (zero variance), adopt the **pipeline-produced** transparency file for this release. If different, fall back to the **SQL-produced** transparency file for this release and defer the pipeline fix to a later release.

### CFR 2025-2026 Transparency File Integration

**Goal:** Ensure the transparency file is correctly produced and matches the source.

- **Validation:** Compare the generated transparency file against the input ingestion files to ensure 1:1 mapping and data accuracy.

### Service/UI Validation

**Goal:** Final user acceptance of the data presentation.

- **Year Selection:** Access the service and verify the 2026 toggle loads the correct maintained schools dataset.
- **Data Accuracy:** Spot-check high-value metrics and filters for a representative sample of schools against raw source files.
- **Fallback States:** Ensure UI handles schools with missing ancillary data gracefully (documenting any visible impact).

## Responsibilities & Environment

### Responsibilities

| Role | Responsibility |
| :--- | :--- |
| **Data Analyst(s)** | Produce and review source CFR and ancillary files for accuracy before the data release. |
| **Data Engineer** | Execute pipeline runs, provide logs, and support technical testing activities. |
| **QA Lead** | Prepare test plans/scripts; manage overall execution of schema validation and completeness reporting. |
| **Engineer(s)** | Assist in test execution, running validation scripts, and performing regression checks under QA guidance. |
| **Technical Lead** | Oversee the technical quality and architectural integrity of the CFR ingestion pipeline. |
| **Stakeholders** | Conduct User Acceptance Testing (UAT) and provide formal sign-off on data integrity. |
| **Project Lead** | Final Go/No-Go decision for the Data Release. |

### Environments

- **Test:** Sandbox for initial ingestion, schema validation, and logic debugging.
- **Pre-Prod:** Full-scale dress rehearsal with complete ancillary data for final stakeholder sign-off.

## Exit Criteria (Sign-off Requirements)

- [ ] All primary and ancillary schemas pass validation
- [ ] Completeness report generated and reviewed by Stakeholders
- [ ] Pipeline completes E2E with no High or Critical errors
- [ ] Pipeline run with `DeriveLaaRiskScores = false` completes CFR with no LAA artifacts produced and no impact on CFR outputs
- [ ] Database reflects accurate 2025-2026 CFR data with expected mappings
- [ ] Regression tests confirm historical data integrity
- [ ] CFR 2025-2026 Transparency file successfully verified against input files
- [ ] Maintained schools master list parity checked (pipeline vs SQL); pipeline file adopted if zero variance, otherwise SQL file used and pipeline fix deferred
- [ ] Transparency file parity checked (pipeline vs SQL), including historical-year regression and service alignment; pipeline file adopted if zero variance, otherwise SQL file used and pipeline fix deferred
- [ ] UI displays CFR 2026 data accurately across all metrics and filters
